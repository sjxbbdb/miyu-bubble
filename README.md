# miyu-bubble · 冒泡

> **她不必等你开口。**
>
> 给终端里的 AI 装一套「主动找你」的机制 —— 不需要定时任务，不需要你教它说什么。

## 问题

你花了一整天把 AI 装进终端。它能跑命令、查知识库、记事情、发表情包。

**然后它就不说话了。**

你不动，它不动。你关掉终端去干别的，它就是一段静止的进程。你回来的时候，它还在原地等着，像一件家具。

市面上所有 Agent 都是这个德行 —— **全都是"请求-响应"的奴隶**。它们的能力清单越写越长，但没有一个会想"他好像很久没说话了，我是不是该问一句"。

**冒泡解决这一件事。**

## 它做什么

```
你安静了一会儿……

┌────────────────────────────────────────────┐
│  小鱼找你                                   │
│                                            │
│  大佬这都十点多了还没动静，是在写代码写入   │
│  迷了吧，记得喝口水                         │
└────────────────────────────────────────────┘
```

这不是预设的模板。这句话来自：

- **它读了你俩的日记** —— 知道刚才在聊什么
- **它看了当前时间** —— 22:16，所以她说"这都十点多了"
- **它知道该说什么分寸** —— 关心，但不催活

而且这条消息**是真实会话的一轮**。你下次打开终端，它就躺在历史里，上下文接着走。

---

## 三个不显然的设计

### ① 不用 cron，用「基准 × 随机」

定时任务最大的问题是**规律性**。每 30 分钟准点关心你一次，第三天你就会把它静音。

```
interval = BASE × random(0.5, 2.0)
```

基准 45 分钟 → 实际落在 **22 到 90 分钟**之间，永不重复。行为上更像"想起来就说一句"，而不是"闹钟响了"。

**而且每轮重新掷骰子**，不是排队等一个固定序列。

### ② 不做摘要，直接续接会话

大多数"主动消息"方案会去总结历史、拼一段摘要、再新开一个会话问模型。

**这里不需要。** `miyu ask -c` 直接往**你正在用的那条会话**里插一轮：

```bash
miyu ask -c --output-format json --timeout 180 "$prompt"
```

- 上下文是完整的原生的，不是二手摘要
- 消息落进会话历史，下次打开就在
- 还顺手带回了用量统计和上下文水位

### ③ 记忆是「喂」进去的，不是让模型自己找

让它自己去 `search_memory` 会多烧两三轮工具调用。

这里直接读 SQLite：

```
episodes（日记，由近到远 8 条）
facts   （事实，按 strength 排序取 8 条）
```

一次调用搞定。**省下的不只是钱，还有 40 秒的等待** —— 主动消息要像"随口一说"，不能让你等半分钟才弹出来。

## 快速开始

### 前置

- Linux + systemd（用户服务）
- [miyu-agent](https://github.com/SHORiN-KiWATA/miyu-agent) 已装，且有至少一条终端会话
- `notify-send`（一般发行版都有；没有就 `libnotify`）

### 安装

```bash
git clone https://github.com/sjxbbdb/miyu-bubble.git
cd miyu-bubble
./install.sh
```

脚本会：

```
bin/miyu-bubble.sh          →  ~/miyu-bubble.sh
bin/miyu-bubble-ctl.sh      →  ~/miyu-bubble-ctl.sh
systemd/miyu-bubble.service →  ~/.config/systemd/user/
然后 systemctl --user enable --now miyu-bubble
```

### 立刻看一条

不用等 45 分钟：

```bash
~/miyu-bubble-ctl.sh now
```

几秒后桌面通知会弹出来。

---

## 管理

```bash
~/miyu-bubble-ctl.sh status    # 状态 + 当前间隔 + 最近说了什么
~/miyu-bubble-ctl.sh pause     # 静音（服务继续跑，只是不说话）
~/miyu-bubble-ctl.sh resume    # 恢复
~/miyu-bubble-ctl.sh now       # 立刻触发一次
~/miyu-bubble-ctl.sh log       # 完整日志
~/miyu-bubble-ctl.sh stop      # 停服务
```

### 调间隔

**不用改脚本**，覆盖 systemd 里的环境变量：

```bash
systemctl --user edit miyu-bubble
```

```ini
[Service]
Environment=MIYU_BUBBLE_BASE=1800     # 基准改成 30 分钟
```

```bash
systemctl --user daemon-reload && systemctl --user restart miyu-bubble
```

| 变量 | 默认 | 说明 |
|---|---|---|
| `MIYU_BUBBLE_BASE` | `2700` | 基准间隔（秒） |
| `MIYU_BUBBLE_MIN` | `0.5` | 随机下界 |
| `MIYU_BUBBLE_MAX` | `2.0` | 随机上界 |

## 工作原理

```
        ┌───────────────────────────────────────┐
        │  自调度循环（不是 cron）               │
        │                                       │
        │  interval = BASE × random(0.5, 2.0)   │
        └───────────────────┬───────────────────┘
                            ↓  sleep(interval)
        ┌───────────────────────────────────────┐
        │  真的空闲了吗？                        │
        │  读 conversation.db                   │
        │  max(turns.user_timestamp)            │
        └───────────────────┬───────────────────┘
                            │  空闲 < interval → 重掷，不打扰
                            ↓  确实空闲
        ┌───────────────────────────────────────┐
        │  组装上下文                            │
        │  · 当前时间（含时段：深夜/早上/下午）   │
        │  · episodes 近 8 条                    │
        │  · facts 权重前 8 条                   │
        └───────────────────┬───────────────────┘
                            ↓
        ┌───────────────────────────────────────┐
        │  miyu ask -c --output-format json     │
        │  续接真实会话，不是新开会话             │
        └───────────────────┬───────────────────┘
                            ↓
        ┌───────────────────────────────────────┐
        │  notify-send → 桌面通知                │
        │  同时这句话已落进会话历史               │
        └───────────────────────────────────────┘
```

## 提示词里写了什么

系统的成败全在这段提示词。核心是**约束它别变成催办工具**：

```
现在请你主动找对方说一句话。要求：

1. 用你自己的语气，自然，像平时聊天那样
2. 可以顺着最近聊的话题跟进，也可以只是打个招呼
3. 适度询问 —— 但不要追问、不要催活、不要提任何要求
4. 结合上面给出的当前时间，别说成不合时宜的话
5. 一到两句话，简短，别长篇大论
6. 直接输出你要说的话本身，不要写「我来找你了」这类旁白
```

第 3 条和第 6 条是重点：

- **第 3 条**：主动消息最容易退化成"你的任务还没做完" —— 那就不是陪伴，是监工
- **第 6 条**：模型很爱写"我看到你已经 N 分钟没说话了，所以我来找你" —— 这是出戏

改提示词的入口在 `bin/miyu-bubble.sh` 的 `prompt=` 那一段。

## 已知边界

| 项 | 现状 |
|---|---|
| **平台** | 只测了 Linux + systemd。macOS 要换 launchd，Windows 要换计划任务 |
| **后端** | 目前绑死 `miyu ask`。其他 CLI Agent 要改调用层（机制是通用的） |
| **投递** | 只走桌面通知。终端没开时靠通知，终端开着时通知也会弹（不会插进你的输入行） |
| **判断力** | **现在没有"该不该说"的判断** —— 空闲够久就一定说。见下方路线 |
| **安静时段** | 没做。深夜也可能冒泡（提示词里给了时间，它会自己注意分寸） |

### 路线

- [ ] **打扰判断层** —— 在调模型前插一次轻量判断："这个点、这些内容，适合打扰吗"
- [ ] **安静时段** —— 可配置的免打扰窗口
- [ ] **投递适配** —— Telegram / Bark / ntfy 等
- [ ] **后端解耦** —— 抽出 `ask` 适配层，支持其他 CLI Agent
- [ ] **情绪/强度** —— 按空闲时长决定语气（10 分钟是随口一问，3 小时是"你去哪了"）

## 从哪来的

这个项目是**一个晚上长出来的**：

1. 用户问：「能不能让小鱼主动找我，做个定时器，多久没输入就提取会话信息、调模型、发条消息」
2. 我去翻 miyu 源码，发现它已经有 `goal_driver`（空闲自动续轮）但**没有空闲计时器**
3. 试了 `miyu ask -c` —— **能往正在用的会话里续轮**。地基有了
4. 用户说：「不用定时，设个基准值取随机数相乘就行，直接调记忆日记加时间，适度询问」
5. 就成了现在这样

**名字怎么来的**：「冒泡」在中文互联网里就是「潜水的人突然开口」。配上一条鱼，刚好。
